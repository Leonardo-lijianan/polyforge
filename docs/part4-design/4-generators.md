# 4. 生成器

生成器是流水线的最后一层：**读 IR，写产物**。

## 生成器列表

按 target 分组。每个 target 是独立完整的生成器集合。

### `--target=frontend`

| 生成器 | 输入 | 产物 |
|---|---|---|
| `frontend/types` | enums + views | TS 类型 |
| `frontend/requestMap` | apis | 请求映射 |
| `frontend/validators` | rules | 表单校验规则（Element Plus 格式） |

### `--target=backend`

| 生成器 | 输入 | 产物 |
|---|---|---|
| `java/entity` | enums + entities | 枚举类、MyBatis-Plus 实体 |
| `java/dto` | views | record |
| `java/mapper` | entities | MyBatis-Plus `BaseMapper` |
| `java/assembler` | views（带 from） | Entity → DTO 视图映射器 |
| `java/service` | apis | Service 接口 + Impl 骨架 |
| `java/controller` | apis | REST 控制器 |
| `java/handler` | —（固定骨架） | `MetaObjectHandler` 骨架（首次创建后保护） |

### `--target=db`

| 生成器 | 输入 | 产物 |
|---|---|---|
| `java/flyway` | entities | 建表 SQL（PostgreSQL / MySQL，由 `outputs.db.dialect` 决定） |

> **命名注意**：`java/mapper` 是 MyBatis-Plus 的 DAO（`BaseMapper`），`java/assembler` 是视图映射器（Entity → DTO）。JPA 时代后者曾叫 `mapper`，与 MyBatis 的 Mapper 撞名后改名。

## 统一约定

生成器是**纯函数**：

```js
export function generateXxx(ir, outDir, basePackage) {
  // 读 ir，往 outDir 写文件
  // 不读源文件、不联网、不依赖外部状态
  // 包名由 basePackage 派生，不硬编码
}
```

- **只读 IR**：不碰 YAML，不重新解析引用
- **输出目录由参数给**：不硬编码路径
- **包名由 `basePackage` 派生**：产物 `package` 行和跨类 import 都跟着走
- **自己创建目录**：`mkdirSync(dir, { recursive: true })`
- **顶部带标记**：产物首行是 `// AUTO-GENERATED by polyforge. DO NOT EDIT.`

> ⚠️ **例外**：`java/service` 多一个 `handRoot`（手写实现目录），`java/handler` 同理。
> 因为它们要管理「骨架保护」。见下。

## 生成器怎么用 IR

生成器靠 `resolved.kind` 判断字段类型，不重新查名字：

```js
function javaType(fd) {
  if (fd.resolved?.kind === 'enum') return fd.resolved.target
  if (fd.resolved?.kind === 'entity') return fd.resolved.target
  return PRIM[fd.type] || /* ... */
}
```

## 手写保护（java/service 独有）

`java/service` 生成两种东西：

| 产物 | 目录 | 覆盖策略 |
|---|---|---|
| Service **接口** | `generatedDir/service` | 每次都覆盖 |
| Service **实现骨架** | `handServiceDir` | 首次创建，之后保护 |

保护逻辑：

```js
function isPureSkeleton(content) {
  // 必须先剥注释：生成器头注释里有 "return" 这个词，
  // 全文匹配会让所有 Impl 永远被保护。
  const stripped = content
    .replace(/\/\*[\s\S]*?\*\//g, '')
    .replace(/\/\/[^\n]*/g, '')
  const overrideCount = (stripped.match(/@Override/g) || []).length
  const throwCount = (stripped.match(/throw new UnsupportedOperationException/g) || []).length
  const hasReturn = /\breturn\b/.test(stripped)
  return overrideCount > 0 && throwCount === overrideCount && !hasReturn
}
```

- **纯骨架**（每个 `@Override` 方法体都是 throw TODO、无 return）→ 刷新
- **有逻辑**（出现 return）→ 保护

> ⚠️ 历史坑（两层）：
> 1. 曾用全文 `/\breturn\b/` 匹配，因头注释含 "return" 导致所有 Impl 永远「保护」。修复后先剥注释。
> 2. 判据曾用外部传入的「当前接口方法数」`methodCount` 比较。接口新增方法后 `methodCount` 变大、旧文件里 throw 数不变，必然不等 → 误判非骨架 → 不刷新 → 编译失败（P0-6）。现在改为**文件内自洽判断**：`@Override` 数 == `throw TODO` 数。

详见[产物](../part3-usage/3-outputs.md)。

## 生成器如何接线

入口 `index.mjs` 的 gen 分支按 target 分组调用：

```js
const wantFrontend = target === 'all' || target === 'frontend'
const wantBackend  = target === 'all' || target === 'backend'
const wantDb       = target === 'all' || target === 'db'

if (wantFrontend && fe) {
  if (fe.types) generateFrontendTypes(ir, fe.types)
  if (fe.requestMap) generateFrontendRequestMap(ir, fe.requestMap)
  if (fe.validators) generateFrontendValidators(ir, fe.validators)
}
if (wantBackend && be) {
  if (!be.basePackage) { /* 报错退出 */ }
  generateJavaEntity(ir, be.generatedDir, be.basePackage)
  generateJavaDto(ir, be.generatedDir, be.basePackage)
  generateJavaMapper(ir, be.generatedDir, be.basePackage)
  generateJavaAssembler(ir, be.generatedDir, be.basePackage)
  generateJavaService(ir, be.generatedDir, be.handServiceDir, be.basePackage)
  generateJavaController(ir, be.generatedDir, be.basePackage)
  generateJavaMetaObjectHandler(ir, be.handServiceDir, be.basePackage)
}
if (wantDb && db?.flyway) {
  generateJavaFlyway(ir, db.flyway, db.dialect || 'postgres')
}
```

> 🔧 **待改进**：接线是手写的 if 链。加一个产物，要改 index.mjs 的多处。
> 理想是「生成器注册表」——每个生成器声明自己对应哪个 output 键和哪个 target。

## 命名：域 → 类名

多数 Java 生成器按「域」分组，生成一个域一个文件：

```
domain: 'award-notice'
  ↓ camel() 转驼峰
'AwardNotice'
  ↓ 加后缀
'AwardNoticeController'、'AwardNoticeService'
```

`domain` 名里的 `-` 会被去掉并转驼峰。
